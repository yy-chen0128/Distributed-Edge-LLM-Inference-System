# 研究主题与论文相关性再评估

> 更新日期：2026-08-06

## 一、研究问题拆解（用户明确）

大目标：**分布式算力单元协作执行训练/推理任务**。拆分为六个子问题：

| 编号 | 子问题 | 说明 |
|---|---|---|
| D1 | 任务拆分 | 把训练/推理任务拆成更小的阶段/部分（模型切分、流水线、阶段分离） |
| D2 | 协作执行 | 多个算力单元如何协同完成一个任务（pipeline、batching、通信协同） |
| D3 | 任务分配/调度 | 任务怎么分配给不同的异构算力单元（放置、调度、负载均衡） |
| D4 | 节点离开/加入 | 中途有节点离开/加入时，任务如何快速装载/卸载、状态如何迁移恢复 |
| D5 | 新单元性能评估 | 新 GPU 到来时如何评估其能力、决定分配多大任务 |
| D6 | 非数据中心通信 | 非数据中心场景（边缘/去中心化/地理分布式）下节点间如何通信 |

> 排除项：激励/信誉机制（如 PolyLink 的区块链代币）、与分布式算力协作无关的方向。

## 二、相关性分层

### 核心必读（直接命中 3 个以上子问题）

| 论文 | 命中 | 为什么相关 |
|---|---|---|
| **Helix** (ASPLOS'25) | D1 D2 D3 D6 | 异构 GPU+网络上的协作推理；模型按层切分→节点；max-flow 把算力/网络都建模为容量；**地理分布式**（非数据中心通信）；联合优化放置与调度。最贴合"异构单元协作 + 网络受限" |
| **SpotServe** (ASPLOS'24) | D3 D4 D5 | **节点离开/加入**的核心：动态再并行化（实例数变化→重排并行度）、实例迁移（二分图匹配最大化复用）、token 级状态恢复、参数/KV 迁移。直接对应"中途离开的快速装载卸载" |
| **Sia** (SOSP'23) | D3 D4 D5 | 异构+弹性联合调度；**通过吞吐模型引导启动评估各 (作业, GPU 类型) 性能**（每类型只 profile 1 个 GPU 就外推）——这正是"新 GPU 评估"的方法；支持弹性扩缩（分配变化时 checkpoint-迁移-恢复） |
| **Metis** (ATC'24) | D1 D3 D5 | 异构 GPU 上自动并行化部署：device group 生成、按算力分配层与数据、profiler+cost estimator——"新单元能力评估 + 任务拆分"的方法论 |
| **LoongServe** (SOSP'24) | D1 D3 D4 | 弹性序列并行：迭代粒度实时调并行度；**零开销 KV 迁移**（prefill 中主动留存 / multi-master 加实例不迁 KV）——"装载卸载"的高效范式 |
| **FastServe** (NSDI'26) | D3 D4 | 迭代级抢占调度（任务如何分配执行）+ KV cache GPU↔host 主动换入换出（内存态装载卸载） |

## 四、研究空白（Gap）—— 你的方向可切入的位置

1. **新 GPU 中途加入的在线性能评估**：现有工作（Sia/Metis/Helix）都是**离线/作业开始时**评估单元性能（profile→建模→分配）。没有工作处理"**任务运行中**来了一块新 GPU，在线评估它、决定能接多少任务、并快速把负载分给它"——这与 D4+D5 结合，是明显空白。

2. **异构边缘节点离开的快速迁移 + 恢复**：SpotServe 做迁移但**强依赖数据中心宽限期**（30s）且假设同类型 GPU；LoongServe 做零开销 KV 迁移但依赖 NVLink/InfiniBand。**低速/不稳定网络、异构节点、无宽限期**场景下的快速装载卸载，是空白。

3. **非数据中心通信受限下的任务切分**：Helix 建模网络但仍是固定集群；Janus/DecTaskOffload 面向动态网络但未处理任务切分粒度。**把"任务切分 + 通信受限"联合**是空白。

4. **把训练和推理统一到一个弹性协作框架**：多数工作只做训练（Sia/Metis/Bamboo/Oobleck）或只做推理（Helix/FastServe/SpotServe）。两套机制不互通。
