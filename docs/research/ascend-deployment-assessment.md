# 昇腾路线评估记录

更新日期：2026-09-09

## 当前结论

昇腾云算力曾被评估为一个可能的真实后端，但当前不再作为项目近期验证资源，也不再作为主线实现路径。近期验证改为使用多张淘汰旧 GPU 卡组成异构小集群。

保留本文档的原因是：昇腾分析仍然说明了本项目的后端边界，即“完整模型服务后端”和“动态层级 StageRuntime”是两个不同问题。将来如果重新获得昇腾资源，可以沿用这一边界重新接入，但当前不为昇腾维护专门的实验路线。

## 已保留的代码能力

`TorchLayeredEngine` 仍然保留：

- `device="cpu"`
- `device="npu"`
- `device="auto"`

这只是设备抽象能力，不代表当前项目计划使用昇腾。当前实际验证优先使用 CUDA 旧卡；NPU 相关分支不纳入近期测试门禁。

## 为什么暂不采用昇腾云算力

当前研究重点是多节点动态调度，而不是单一硬件后端适配。若只有一张昇腾卡，无法充分验证：

- 跨卡 activation 通信；
- 多节点流水线；
- 节点离开和加入；
- 跨节点参数与 KV 迁移；
- 异构能力差异；
- 多链路带宽和故障恢复。

相比之下，多张淘汰旧 GPU 卡虽然性能较弱，但能直接形成多节点或多逻辑节点验证环境，更贴合当前研究目标。

## 后续若重新接入昇腾

未来如果重新使用昇腾资源，应将其作为一个新的硬件后端适配任务，重新确认：

1. NPU 型号、驱动、CANN、PyTorch、torch-npu 和推理运行时的兼容矩阵。
2. 完整模型服务是否能通过 OpenAI 兼容接口接入。
3. 是否能运行自研 StageRuntime。
4. 是否有多卡或多节点资源支持真实流水线和迁移实验。

在这些条件满足前，昇腾仅作为可选后端，不影响当前旧卡主线。
